## Task 76: bug 16

- Investigate and fix GH bug #16

**Root cause (two bugs).** (1) NR 0x1E/0x1F "active video line" returned the raw
frame vc, but VHDL (`zxnext.vhd:5982-5986`) reads `cvc` — the paper-relative
copper-offset counter. The ~64-line origin error corrupted `waitForScanline()`,
shifting David Crespo's videoint scroll ~24 rows down. (2) Once (1) put the split
at the right place, a per-scanline off-by-one showed: the tilemap scroll latched
the END-of-scanline value per row (and end-of-frame clobbered row 255) instead of
the START-of-scanline value, so the HUD split landed one row early.
Fix: NR 0x1E/0x1F return `cvc` (`current_cvc()`); tilemap scroll latches at the
current fb_row in `on_scanline()`, redundant end-of-frame snapshot removed.
Verified against VHDL + CSpect (DZRP: frame-INT line == 248) + real Next hardware.
