# Tasks

## Task 21: profiler

New function: profiler.

Goal: histogram of execution time per address (with physical bank
distinction), so hot functions can be found as optimization candidates.
Primary target: 128K or Next games with banked code.

### Design (agreed 2026-05-29)

**Counters**
- Primary key: physical-bank address in the form `bbNNNN` (bank byte +
  16-bit offset). Covers ~2 MB SRAM + ROM regions ≈ 2 M counters.
- Each entry stores: `uint64_t tstates` + `uint16_t last_logical_pc`.
  The logical PC is overwritten on every hit at that physical address;
  for stable banking layouts (128K / Next games keep code at one slot)
  this is effectively constant and matches what the z88dk `.map`
  contains. Size per entry: 10 B → ~20 MB total, mmap'd so untouched
  pages cost nothing.
- Allocated only when profiling is active.

**Increment**
- Accumulate **T-states**, not fetch counts: `if (profile_active_)
  profile_[phys_addr] += instr_tstates;`
- Branch-gated so non-profile runs see zero cost.
- Hooked at the end of each instruction once `instr_tstates` is known,
  using the same physical-address translation the memory path already
  performs.

**CLI**
- `--profile` — enables profiling.
- `--profile-output FILE` — optional output path; defaults to
  `profile.dat`.
- Pairs naturally with `--delayed-automatic-exit N` for bounded runs.

**Output file format**
- Plain text, sorted by physical address ascending.
- Three columns per line:
  `<physical_hex_bbNNNN> <logical_hex> <tstates_decimal>`.
- Logical = last-observed logical PC at that physical address.
- Zero-count addresses omitted.
- Written on emulator exit.

**Post-processing script** (separate, Perl)
- `get-function-heatmap.pl -m <z88dk-map>` — reads profile data on stdin.
- Parses z88dk map file; keeps **only code-section labels** (filters out
  data / constants / section anchors).
- For each profile line, binary-searches the sorted label list to
  attribute the count to the enclosing function (label[i] ..
  label[i+1]-1).
- Output: function name + accumulated T-state count, sorted descending.
- Map-file physical-address format (`bbNNNN`): deferred — handle once
  the basic logical-PC path is solid. Until then, the script joins on
  the logical column (column 2) of the profile data.

### Implementation notes

- Counter array allocation gated on `--profile`; normal runs allocate
  nothing.
- Physical-address translation already exists in the MMU read path —
  reuse it; do NOT duplicate the slot lookup.
- 64-bit counter array is ~16 MB — `mmap(MAP_ANONYMOUS)` so the kernel
  only commits pages actually touched. Sparse address coverage stays
  cheap in RAM.
