  ## Task 64: investigate github issue 10

  - Again, some clues about X11 interaction...?
  - You can extract NEXTEST.nex from the sdcard image, it's in the /EXTRAS/NEXTEST directory.
  - Extract it and add it to the test suite

- **Root cause:** NEXTEST.NEX is a NextZXOS *application*, not a standalone NEX. The NEX program
  is only ~48.5 KB (512 header + `num_banks=3` × 16 KB); the file is 26,025,651 bytes because
  ~25.9 MB of audio + SD-read-test payload is appended (ends in ASCII "EOF"), which NEXTEST
  streams from its own file at runtime via the NextZXOS API (guide: "continuously streams data",
  "looping audio track streamed from the SD card"; needs NextZXOS 2.1+/core 3.00+).
- `--load` / File→Open injects only the 48.5 KB program onto a bare machine — no NextZXOS, no
  file handle — so NEXTEST dies at its startup OS/SD verification with a silent black screen (no
  error text even). Reproduced headless; **identical on X11 and Wayland → display server NOT
  involved, X11 is a red herring.** Works via the NextZXOS browser (jorgegv confirmed) because that
  boots the OS and hands it the launch context. Same limitation as real hardware.
- Web search: no "corrupted NEXTEST" reports; SpecNext wiki confirms it's the factory soak-test
  that streams from the SD. The 26 MB size is legitimate, not corruption.
- **Fix:** `NexLoader::load()` rejects "extended" NEX files (file substantially larger than the
  header's banks+screens describe, one 16 KB bank of slack) with a clear "run it under NextZXOS"
  message instead of a black screen. All 35 checked-in NEX match their declared size exactly → no
  false positives. Test `nex-extended-reject-func` synthesises the files (**NO 26 MB binary in
  git** — never). Committed `824d7fc8` on branch `fix/issue10-reject-container-nex`; triplet green
  (unit 4689 / FUSE 1356 / regression 86); independently reviewed (result pending at handover).
- **GitHub reply posted** to issue #10 (terse: NextZXOS app, use the browser, X11 not involved).
- **"add NEXTEST to test suite" sub-task DROPPED** — 26 MB and un-runnable via --load; the
  synthesised reject test replaces it.
