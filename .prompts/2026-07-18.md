### Task 63: github issue #9 — beast graphics on NVIDIA/X11 — OPEN (awaiting danboid)

**REFRAMED (2026-07-18): a presentation artifact, NOT frame pacing.** danboid:
"same issues WITH or WITHOUT --silent", and "59 fps under --silent but all the
graphical issues persist." 59 fps on a 60 Hz demo is correct → the frame RATE is
fine; the earlier audio-pacing theory does not explain the real complaint. The
bug is GRAPHICAL at the correct fps (beast/fences/mountains too fast, trees don't
scroll), reproduces ONLY on his 2 NVIDIA-GPU/X11 laptops, never on the owner's
Intel/Wayland/VM/Flatpak with the SAME binary → a display/present artifact, not
emulation logic.

Mechanism (~65%, code-grounded): `EmulatorWidget` is a plain QWidget (no vsync)
that calls the coalescible `update()`; the FPS counter counts EMULATED not
PRESENTED frames, so dropped/uneven presents on the NVIDIA/X11 backing-store path
are invisible to it and read as parallax judder (fast layers skip, slow layers
stutter). The SDL frontend uses `SDL_RENDERER_PRESENTVSYNC`; the Qt one has
neither — the asymmetry.

Diagnostic branch **`task63-beast-nvidia` (PUSHED to origin, commit 05d70674)**
adds `--log-level platform=info` diagnostics (emulated-vs-presented cadence +
dropped count, display stack / DPR / refresh, audio-catchup tally) + opt-in
**`--present-sync`** (repaint() instead of update() → non-coalesced present).

NEXT:
- danboid builds the branch and pastes the `cadence:` lines. `presented ≪
  emulated` (positive `dropped`) confirms the mechanism; then try `--present-sync`
  (dropped→~0 + smooth = fix).
- Free tests, no rebuild: `QT_QPA_PLATFORM=wayland ./jnext …`, and nvidia-settings
  "Force Full Composition Pipeline".
- Durable fix if confirmed: wall-time-gated present, or an opt-in QOpenGLWidget /
  vsync'd present path. Then normal review + triplet + merge.

- Functional/unit tests exercising the feature must be included in the PR
- No existing tests can be modified in the PR. If some need to be, an explicit justification and human approval from JNext owner is needed
- Ensure any fixtures needed for the tests are license-compatible with the project. Don't include proprietary content for tests.
- Code quality and alignment with the rest of the project
- Adding a new dependency (library, tool...) is not allowed, and must have a manual human approval from the JNext owner.

## Task 88: unit-test harness manifest guard fires spuriously after a clean build

Found incidentally while running the Task 83 triplet (2026-07-18).

`make unit-test` FAILED twice with its own "TEST HARNESS REFUSES TO RUN" guard
when invoked immediately after `make clean && make gui-release`, with a
**different** complaint each time:

1. `registered by CMake but MISSING from test/unit-tests.conf: multiface_test`
2. `declared in test/unit-tests.conf but NOT registered by CMake: audio_pacing_test`

Re-running with **no rebuild and no file changed** succeeded, repeatedly. Both
named suites are unrelated to the branch under test.

Why it matters: this guard is what makes the test-count denominator
trustworthy (it exists because three suites once vanished from the totals —
Tasks 32/35/37). A guard that is intermittently wrong trains everyone to
re-run until green, which is exactly the reflex that would let a REAL manifest
mismatch through.

Notes:
- The two complaints point in OPPOSITE directions, so a single "partial read of
  `build/test/CTestTestfile.cmake`" race does not obviously explain both.
- The Task 83 reviewer independently hit a THIRD variant in its own worktree:
  `sd_rom_extractor_tests` (CMake `add_test` NAME, plural) vs
  `sd_rom_extractor_test` (manifest entry, singular). That one may be a real
  pre-existing naming mismatch rather than a race — worth checking first, since
  it is deterministic and cheap to confirm.
- Hypothesis (UNPROVEN): a race between the parallel `cmake --build -j12`
  completing and the generated `CTestTestfile.cmake` being fully visible to the
  next command in the same make recipe.

Do: reproduce deterministically, establish the real mechanism (do not assume
the race), fix, and add a harness-selftest row that would catch it. Treat a
guard that can be wrong as a defect in the guard, not noise.
