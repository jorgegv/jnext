## Task 13: Snapshot / Save-State work

### 13a — Next-specific snapshot schema (G66 + G67) — PARKED

Low priority, needs thoughtful design before any code is written. The proposed shape (4-byte magic + `SCHEMA_VERSION` u32 head + per-subsystem `tag(u16) + length(u32) + payload` framing + magic-mismatch reject + migrator registry) is a multi-week change touching all 27 subsystems with `save_state`/`load_state` methods. Open architectural questions:

- Tag assignment (enum vs string-keyed vs implicit-by-order)
- Migrator API (`migrator(reader, writer)` transcode vs `migrator(reader)` in-place patch)
- Unknown-tag policy on load (strict reject vs skip+warn vs lenient)
- Magic+version placement (top-of-stream once vs per-subsystem)
- Backwards compat at v1 (hard-cut vs accept-legacy-unframed)

Coverage today: rewind_test 10 SKIPs (SS-VER-01..07 + RB-FRAME-01..03) all marked `(see G66)` / `(see G67)`. They will stay as SKIPs until the design lands.

Resume trigger: when the user wants persistent / cross-version save-states (e.g. Save/Load Snapshot menu wired to a `.jnxs` format).
