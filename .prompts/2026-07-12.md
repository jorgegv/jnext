## Task 31: compositor stencil mode ignores the ULA enable (VHDL 7130)

- Found 2026-07-12 during the Task 22b review. Pre-existing emulation bug on
  the real hardware path — nothing to do with the layer mask.
- `zxnext.vhd:7130` gates stencil on `ula_stencil_mode_2 = '1' and ula_en_2 =
  '1' and tm_en_2 = '1'`. `Renderer::composite_scanline` omits the `ula_en`
  term, so a guest that disables the ULA mid-frame (NR $68 b7) under tilemap
  stencil mode keeps the AND-branch selected and gets the NR $4A fallback
  where the VHDL requires the tile pixel.
- Reproduced empirically (throwaway test row, reverted): no layer mask,
  stencil on, tm_en on, ULA disabled → jnext emits `0xFF009200` (fallback);
  VHDL requires `0xFFDD00DD` (tile).
- Needs plumbing: `composite_scanline` has no `row`, so it cannot read
  `ula_enabled_per_line_[row]` today. That is the natural scope of the task.
- `test/00regression/nex/stencil_test.nex` (added by Task 22b) is the fixture.

## Task 33: test/lint-assertions.sh hangs if anything pipes into its stdin

- Found 2026-07-12 during the Task 22b review. Pre-existing. **Corrected the
  same day** — the first write-up of this task claimed the lint was a vacuous
  no-op inside `regression.sh`. That was wrong, and the correction matters:
  with ripgrep 14.1.1 the lint **does** scan the tree correctly under
  `regression.sh` (it finds the 2 known baselined tautologies). The guard is
  working. Do not "fix" a bug that isn't there.
- The real, narrower defect: the three `rg` calls pass glob filters but **no
  path argument**, so if stdin is ever a live pipe ripgrep reads *stdin*
  instead of the tree and blocks forever (`yes | bash test/lint-assertions.sh`
  → hangs until killed). The project's documented invocation never pipes into
  it, so this is latent, not active — but it has already cost an agent several
  hung runs and left stale processes behind.
- Fix: give `rg` an explicit `test/` path argument, which closes the hang and
  makes the intent explicit. Cheap; worth doing.
- Optional hardening: a self-test that fails if a known-bad pattern is *not*
  detected, so the guard cannot silently regress into a no-op in future.

## Task 34: save_screenshot_png()'s failure is discarded — exits 0 with no PNG

- Found 2026-07-12 during the third Task 22b review. Pre-existing (predates the
  branch; confirmed against `e8ab188a`).
- `save_screenshot_png()` already detects and logs I/O failure (bad path, disk
  full, permission denied) and returns `false` — but **all three call sites
  discard the return value** (`headless_app.cpp:215`, `qt_app.cpp:331`,
  `sdl_app.cpp:236`). The countdown is set to `-1` ("done") regardless and the
  process exits 0 with no PNG written.
- That is the *same externally-observable failure* Task 22b just closed for the
  paused-debugger and auto-exit-too-early routes, reached instead via I/O
  failure. The contract now exists ("a screenshot never taken is an error +
  non-zero exit"); this is the one path that still escapes it.
- Fix: honour the `bool`, log at `error`, set the non-zero exit code — same as
  the other two routes. Test with an unwritable path.

## Task 35: `make clean && make gui-release` silently drops rewind-func

- Found 2026-07-12 during the third Task 22b review. Pre-existing harness gap.
- `make clean` runs `unit-test-clean`, which deletes `build/test/rewind_test`.
  `regression.sh:501-502` gates the `rewind-func` block on
  `[[ -x "$REWIND_TEST" ]]` and, when it is absent, prints **no row at all** —
  not a SKIP, not a FAIL. The suite total silently goes 57 → 56 and the missing
  test is invisible.
- So the project's own documented pre-regression incantation (`make clean` +
  `make gui-release`) is not sufficient to run the full suite; it needs
  `make unit-test-build` as well. That is a trap, and it has already produced
  two different "correct" totals in one day.
- Fix: make the absent-binary case print an explicit SKIP row (so it can never
  vanish silently), and either build `rewind_test` as part of the regression
  target or document the extra step in CLAUDE.md. A test that can disappear
  without a trace is worse than one that fails.
