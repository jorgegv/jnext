## Task 39: **URGENT — NEXT UP.** Cut the test/review cycle time

Measured 2026-07-12. Machine: **12 cores, 61 GB RAM**. A triplet is ~**5 min**
(4m23s and 4m58s on the two post-merge runs); reviews ran **13–40 min**, dominated
by mutation cycles (revert → rebuild → run → restore → rebuild → run, ×2-4). The
goal is a faster loop with **no reduction in work or rigour**.

Three fixes, in payoff order:

1. **Wire ccache into the build — biggest win.** `ccache` IS installed
   (`/usr/bin/ccache`) but jnext **bypasses it**: `build/CMakeCache.txt` shows
   `CMAKE_CXX_COMPILER=/usr/bin/g++`, and `CMakeLists.txt` sets no
   `COMPILER_LAUNCHER`. (The 27% hit rate visible in `ccache -s` is some *other*
   project; jnext contributes nothing.) Every rebuild is a cold compile — and the
   review loop rebuilds the world repeatedly, which is exactly where the time goes.
   - Add `find_program(CCACHE ccache)` → `CMAKE_C_COMPILER_LAUNCHER` /
     `CMAKE_CXX_COMPILER_LAUNCHER` in `CMakeLists.txt`, guarded so a machine
     without ccache still builds.
   - Raise the cache: `ccache -M 20G` (currently **5 GiB, already 3.9 used** — it
     would thrash immediately on a project this size).
   - Keeps the `make clean` discipline affordable: a clean rebuild after reverting
     one file becomes mostly cache hits, so we keep the safety without the cost.

2. **Stop hard-forcing `JNEXT_TEST_JOBS=4`.** `regression.sh:109` already defaults
   to `nproc` (12). The 4-cap comes from the day six concurrent agents each
   launched an unbounded regression and crashed the machine twice — it is a
   **multi-agent contention** rule, never a per-run requirement. Single regression
   on 12 cores should use **8**; keep 4 only when ≥3 agents run concurrently.
   Most of the ~46 headless emulator runs then go ~2× wider.

3. **Run reviewer mutations concurrently.** They are independent by construction
   (reverting the stencil gate has nothing to do with reverting the tab order), yet
   today they run serially in one worktree. Give each its own build dir and run
   them in parallel — this is the 40-min review becoming ~15.

Do **not** touch: `make unit-test` already fans all 44 suites out in parallel
(`Makefile:141-143`) — it is not the bottleneck. And do not relax `make clean`;
fix (1) is what makes it cheap.

Verify: time a triplet before and after; report both numbers. No test may be
dropped, skipped, or made less discriminative in the name of speed.

## Wayland window bug — DONE (unnumbered), merged 669baa6a

Found while the user was being hit by stray emulator windows during test runs.

- `audio-underrun-func` is the **one** test that cannot use `--headless` (it needs
  a real audio path), so it runs the *windowed* emulator under `xvfb-run`. But
  `xvfb-run` only sets `DISPLAY` — it leaves `WAYLAND_DISPLAY` alone, and Qt/SDL
  **prefer Wayland**. So the emulator ignored the virtual X display it was handed
  and opened a **real window on the user's desktop**, once per regression run.
  Proven by strace: **2 connects to `wayland-0`**, zero to the Xvfb X socket.
- Fix: unset `WAYLAND_DISPLAY` and force `QT_QPA_PLATFORM=xcb` +
  `SDL_VIDEODRIVER=x11`, confining it to the Xvfb display.
- **NOT done, deliberately:** pointing `WAYLAND_DISPLAY` at a dead socket. It does
  kill the last libwayland probe (unsetting alone is not enough — libwayland falls
  back to the default name `wayland-0`), but SDL then finds no audio backend and
  the test **SKIPs** with "no audio captured". A stray window is not worth trading
  for a silently-disabled test. The comment in `regression.sh` says so, to stop

## Tasks 32 / 35 / 37 — the joint fix: the suites are DECLARED, and the harness proves it ran them

One bug with three faces, fixed once, the way the user specified: **the test list
(executables included) is a config file, the harness runs exactly what it names, and
anything missing is a loud failure — never a silent skip.**

**The manifests**
- `test/unit-tests.conf` — all 46 unit suites (+ args). Read by the new
  `test/run-unit-tests.sh`, which replaces the 60-line list-and-loop that lived inside
  the Makefile. The old list was hand-kept, which is precisely how it drifted.
- `test/00regression/functional_tests.conf` — the 12 functional tests
  (`regression_tests.conf` already declared the 46 screenshots).

**Five ways a test used to vanish; all five are now loud (exit 2, before anything runs):**
1. registered in CMake but missing from the manifest → **refuse to run** (Task 32's bug)
2. named in the manifest but not registered in CMake → **refuse to run** (stale entry)
3. named in the manifest but not built → **refuse to run**
4. runs, exits 0, prints no parseable `Total:` line → **FAIL** (it used to score PASS
   with 0 rows — a suite that asserts nothing was indistinguishable from one that passed)
5. a declared functional test reports no row, or the grand total ≠ 1 lint + screenshots
   + functional → **harness fault**, "treat this as RED, not as a pass"

The CMake side is not a second hand-kept list: it is read from the generated
`build/test/CTestTestfile.cmake`, so the manifest is checked against what the build
*actually registered*. **Every one of the five was proven to fire** by injecting the
fault and observing the refusal.

Also: `make unit-test` now **exits non-zero when a suite fails** — it used to exit 0
regardless, so a failing suite could not fail a script.

**The independent review caught two blockers, and it was right about both.**
- **The harness broke in the one case that matters: a suite that FAILS.**
  `set -euo pipefail` is inherited by the `( … ) &` runner subshell, so a suite exiting
  non-zero — i.e. *any* failing test, the normal failure path — killed the subshell
  **before** it recorded the exit code; the aggregator's `cat` then failed and errexit
  **aborted the whole run**, dropping every suite after the failing one, printing no
  grand total. All 46 suites pass today, which is exactly why it hid: the first version
  was verified only against suites that pass, and against a stub that exits **0**.
  A harness that under-reports precisely when something is wrong is worse than none.
- **The regression completeness check was tautological on its screenshot term.**
  `expected` was computed from the same conf the run iterates, so both sides shrank
  together: deleting 44 of the 46 screenshot rows produced a green
  *"15/15 declared tests reported"*. That is Task 32's bug, reintroduced inside the fix
  for Task 32. The fix uses an **independent witness** — the checked-in
  `img/<name>-reference.png` files, which do not vanish when the conf is truncated.

**So the harness is now itself under test** (`test/harness-selftest.sh`, 14 cases, run by
`make harness-selftest` and as `harness-selftest-func` in every regression). It injects
each fault against stub suites and asserts the refusal — including a failing suite, a
segfaulting suite and a hanging one. Proven discriminative: against the shipped (buggy)
harness it FAILs HS-02/03/04; against the fixed one all 14 pass.

**Row counts are now pinned per suite** (user's call — the "hard pin" option): the manifest
carries each suite's exact `Total:`, and any deviation fails. That closes the last face of
the bug — a suite that quietly stops emitting rows (Task 37's `sd_rom_extractor_test`
reporting 8 rows when it has 26) is no longer invisible. Adding or removing a test row now
means updating the count, deliberately.

**Bonus bug, found by running the tests without the `LANG=C` prefix I had been using
out of habit** (unnumbered, fixed here): `screenshot-io-qt-func` greps the emulator's
error output for `"No such file or directory"`, but **Qt's `QApplication` constructor
calls `setlocale(LC_ALL, "")`**, so on this Spanish desktop `strerror` returned
"No existe el fichero o el directorio" and the test **FAILed** — while its headless
twin (no QApplication, so still in the C locale) passed. The suite's verdict depended
on the user's `LANG`. `LC_ALL=C` is now pinned in `regression.sh`,
`run-unit-tests.sh`, the `Makefile` (all recipes) and on all 46 `add_test()`
registrations, so `ctest` agrees too.
