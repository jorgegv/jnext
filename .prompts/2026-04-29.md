## Task 2: NR 0x07 turbo handling defect (open backlog)

Surfaced 2026-04-26: writing `NR 0x07 = 0x03` (turbo 28 MHz) in
`Emulator::nex_init_machine` causes `tilemap-demo` (regression test)
to render BLACK SCREEN. Confirmed interactively. Likely a jnext-side
defect in turbo handling — possibly:
- Tight scanline-synchronized demo loops calibrated for 3.5 MHz miss
  their target at 28 MHz (could be VHDL-faithful behaviour but
  unfortunate)
- Effective T-state accounting at 28 MHz has a bug in jnext

Today's note (2026-04-28): NR 0x07 commit edge work landed under G142
(bus-idle deferred commit) and G51 (combined NR 0x07+NR 0x08 b6 commit
ordering). The synchronous-commit bug at line :322-326 has been
addressed; pending commit happens on bus-idle now. **Re-run the
turbo-demo black-screen reproduction to see if G142 already fixed it.**
If it still reproduces, investigate further.

**RESOLVED 2026-04-29 (commit `346b53b`).** G142 did NOT fix it. The
defect was NOT NR 0x07 / turbo / contention — it was a per-scanline
change-log vblank-flush gap in PaletteManager (and 5 other logs:
Layer2's 5 sub-logs, SpriteEngine, Ula port-0xFF / scroll / palsel).
At NR 0x07 ≥ 0x02 the demo's NR 0x40/0x41 setup completes during
vblank, so the rewind+per-line-replay loop in `Renderer::render_frame`
never replayed those entries and the next frame's `start_frame()`
snapshotted a baseline missing them. Tilemap NR 0x6B already had
`flush_remaining_nr6b_changes()` from W2; the fix mirrors that
pattern uniformly across the other 6 logs. tilemap_demo now renders
correctly at 28 MHz; parallax unchanged (md5 identical pre/post fix).
Aggregate 3729/3544/0/185 (+6 PSCAN-VBLANK-* tests); regression
34/0/0 (rebaselined `dapr-sprite` + `dapr-tilemapper_01`).

## Task 3: tbblue nexload.asm 6-NR init bundle

**RESOLVED 2026-04-29 (commit `4f142a4`).** Bundle landed in
`Emulator::nex_init_machine` (`src/core/nex_loader.cpp:300-322`):

  - NR 0x06 = 0xA8 — peripheral 2 (preserves bits 7+5 F8/F3 enables
    from the 0xA0 reset baseline; clears bit 4 DivMMC autopage; sets
    bit 3 Multiface)
  - NR 0x07 = 0x03 — turbo 28 MHz
  - NR 0x08 = 0xCE — peripheral 3 (disable locked paging, disable
    contention, stereo ABC, enable specdrum/timex/turbosound)
  - NR 0x42 = 0x0F — ULANext format with flashing enabled
  - NR 0x61 = 0x00 — copper-control LO byte (stop)
  - NR 0x62 = 0x00 — copper-control HI byte (stop)

Source-of-truth: `tbblue/src/asm/nexload/nexload.asm:322-365`. Note
the investigation doc had referenced a non-existent NR 0x44; the
actual nexload.asm has 6 writes, not 7.

Six regression screenshots shifted; **all six rebaselined under
explicit user authorisation**: `palette-demo`, `floating-bus`,
`tilemap-demo`, `contention-test`, `dapr-sprite`, `dapr-tilemap_00`.
(Note: `dapr-sprite` was rebaselined a second time — once as part of
Task 2, once again here as the bundle shifts it further. Same for
`dapr-tilemap_00`.)

Aggregate 3729/3544/0/185 unchanged; regression 34/0/0. Reviewer:
