## Task 60: bugs found during Task 27a (non-optimization follow-ups)

Surfaced by the Task 27a architecture assessment. None are performance items; each needs its
own branch, fix, test and independent review. **All three verified by direct inspection, not
taken on an agent's word.**

- **60a — Debugger single-stepping silently drops interrupts.** `Emulator::run_frame()` ticks
  `im2_`, `md6_` and polls the pulse-mode `/INT` line every instruction
  (`emulator.cpp:6619`, `:6804`, `:6722-6727`). `Emulator::execute_single_instruction()`
  (`emulator.cpp:7036-7163`) — the path the debugger uses to step — ticks only `ctc_`, `uart_`,
  `nmi_source_`. It **never calls `im2_.tick()`** and never polls `pulse_int_n()`. IM2 is what
  delivers interrupts to the CPU, so while single-stepping, CTC/UART/ULA-frame interrupts are
  never delivered: stepping through an ISR-driven program does not reproduce free-running
  behaviour. Root cause: `execute_single_instruction()` is a hand-maintained copy of the
  `run_frame()` inner loop and has drifted (its own comments claim it "mirrors the primary
  cluster"). Fix: extract one shared `step_one_instruction()` that both call.
- **60b — `Saveable` is a dead interface.** `src/core/saveable.h:106` declares a pure-virtual
  save/load base. **No class in `src/` or `test/` inherits from it** (verified). All ~22
  subsystems duck-type `save_state`/`load_state`, and `Emulator::save_state`/`load_state`
  (`emulator.cpp:7944` / `:8108`) are ~60 hand-ordered calls that must stay in lockstep by
  convention alone — the header comment at `:7925` says exactly that. Either make subsystems
  implement it and iterate a `vector<Saveable*>`, or delete the class. Also: `StateWriter`/
  `StateReader` store a `capacity_` they never check (`saveable.h:51`, `:102`) — an asymmetric
  save/load edit corrupts every subsequent subsystem's state silently, with no sentinel to catch it.
- **60c — `src/input/` is entirely absent from snapshots.** No file under `src/input/` has a
  `save_state` (verified), and `Emulator::save_state` references no input subsystem (verified,
  0 hits). Keyboard, Joystick, Mouse, IoMode, MembraneStick and Md6ConnectorX2 are all lost
  across a rewind/snapshot. `Md6ConnectorX2` is the sharp case: it has a live 9-bit FSM ticked
  every instruction (`md6_connector_x2.cpp:245`) that silently vanishes. `SdCardDevice` has the
  same hole and at least documents it (`sd_card.h:173-179`).

- **60d — IM2 pulse counter runs 8× fast at 3.5 MHz (the default).** Commit `314a752d`
  ("pulse_count_ ticks per CPU T-state, not per Z80 instruction") rewrote `im2.cpp` and left a
  comment (`im2.cpp:67-76`) stating the caller "now passes `tstates`, not `tstates × cpu_divisor`"
  — **but it never changed the caller**. `emulator.cpp:6619` passes `master_cycles`
  (= `tstates × cpu_divisor`, set at `:6595`) and always has: git-verified, `im2_.tick(tstates)`
  never existed in the history. So `pulse_count_advance_` (`im2.cpp:82`, consumed at `:1204`,
  whose own comment says "4..23 per Z80 instruction") receives 8× its intended value at 3.5 MHz
  and is correct only at 28 MHz. Either the code or its VHDL-cited comment is wrong; both are
  load-bearing. Investigate against `zxnext.vhd:2037-2044` before calling it a bug.
