## Task 1: NextZXOS boot — PRIMARY FOCUS

Trace and unblock the SKIPs that gate NextZXOS booting end-to-end. (This task subsumes the former Task 12; full chronological history is preserved in [doc/issues/nextzxos-boot/NEXTZXOS-BOOT-INVESTIGATION.md](../doc/issues/nextzxos-boot/NEXTZXOS-BOOT-INVESTIGATION.md) and [doc/issues/nextzxos-boot/G46B-INVESTIGATION-LIVE.md](../doc/issues/nextzxos-boot/G46B-INVESTIGATION-LIVE.md).)

### Open gaps

- **G46(b)** — supervisor in NR-init soft-reset loop (matches EOD-14c pre-Divergence-A pattern; 5 soft resets + 98 NR_07 writes in 15 s). Per EOD-26 P4 ([doc/issues/g46b-v2/EOD-26-cspect-comparison-ramclear.md](../doc/issues/g46b-v2/EOD-26-cspect-comparison-ramclear.md)): supervisor commits `machine_type = ZX_PLUS3` via `NR $03 = $B3` mid-boot (intentional). In +3 mode `current_sram_rom()` delegates to `current_rom_bank()` (2-bit composite, the pre-Divergence-A formula). With `NR $8C = $00` (no altrom-lock), wrapper toggle `$7FFD=$10/$1FFD=$04` maps slot 0/1 to enNextZX block 3 = `F3 AF 01 3B 24 C3 E8 3B` = soft-reset trampoline → cycle. Branch `g46b-investigation-v2` HEAD `02e847ac`, +9 vs main `a84dca1f`, NOT pushed.
- **G47** — post-boot regression / dot-command surface. Blocked on G46(b) landing.
- **G59** — bypass-tbblue-fw alternative path (H-effort, can run in parallel).
- **G60** — config.ini parsing (depends on G59).

The `nmi_test` BOOT group has 6 SKIPs gated on these gaps: BOOT-LOOP-01, BOOT-LOGO-01, BOOT-DOT-01, BYPASS-CLI-01, BYPASS-FAT-01, BYPASS-INI-01.

### Prioritized next-session moves (G46(b) priority)

**Single highest-leverage experiment first — the rest branches off its result.**

1. **CSpect DZRP capture at the bank-flip wrapper moment** (decisive, ≈30 min).
   Set a CSpect-side BP at the equivalent of jnext's `$5B0E` (locate the
   wrapper byte-pattern in CSpect's bank-5 RAM, then BP its first OUT). At
   the hit, dump: `NR $8C`, `NR $50..$57`, slot 0/1 effective pages,
   `port_7ffd`, `port_1ffd`, `machine_type` (via NR $03 readback). Diff
   against jnext's probe output (mach=3, nr_8c=00, sram_rom=3,
   slot[0,1]=06,07). The differing register names the missing init step.
   This experiment selects between candidates A/B/C below.

2. **Candidate A — NR $8C altrom-lock should be set but isn't.** Probe
   currently shows `nr_8c=00`. Trace every write of NR $8C (jnext side, env-
   gated). If supervisor never writes it, the gap is upstream. If supervisor
   writes a value that jnext applies incorrectly, the gap is in NextReg's
   NR $8C handler. Cross-reference with TBBlue source at `../tbblue/` for
   `nr_8c` / `$8C` writes during boot.

3. **Candidate B — AltROM SRAM-page layout mismatch.** Commit `0b7c3c25`
   loads `enAltZX.rom` (32 KB) into SRAM pages `0x0C..0x0F` via
   `Mmu::altrom_sram_page_()`. The wrapper's +3-mode toggle expects physical
   pages `0x06,0x07`. Either AltROM must be loaded into different pages, OR
   `NR $8C` must route slot 0/1 to AltROM pages via the lock mechanism, OR
   the layout mapping is correct and Candidate A is the real gap.

4. **Candidate C — DivMMC AUTOMAP timing.** Per Probe 11 (commit `e2b1ddbf`
   on `g46b-investigation-archive`): jnext has AUTOMAP ON at the wrapper
   moment; CSpect has it OFF. The `b849c441` fix (now `5369e5d6` on main)
   models the AUTOMAP gate, but the OFF-trigger timing for this specific
   boot phase may not be captured. Add probe at `divmmc.cpp::check_automap`
   logging when automap toggles + comparing to CSpect via DZRP.

5. **Candidate D — Video subsystem Task-2-style audit** (escalation if
   A/B/C don't yield; H-effort). Per [TASK-14-TEST-STRATEGY-ANALYSIS.md](TASK-14-TEST-STRATEGY-ANALYSIS.md)
   Q1: Task 2 audited Memory + DivMMC/SD/SPI + NMI/MF/Port/NextREG + CPU/Z80N/IM2
   but NOT `src/video/{timing,ula,sprites,layer2,palette,tilemap}.cpp` or
   `src/audio/`. Both prior G46(b) stall sites (sprite-descriptor read,
   vsync-driven HALT loop) live in `src/video/`. The CPU /INT fabric was
   audited from the **consumer** side; the **producer** side (scanline-
   counter phase, 36-T pulse width for Next mode) was not. Run a 3-agent
   parallel sweep over `src/video/{timing.cpp, ula.cpp, sprites.cpp}` with
   the Task-2 methodology (enumeration table + VHDL oracle + reviewer +
   fix-of-reviewer). Defer until A/B/C are exhausted — Task 2 cost ~25
   passes for 4 subsystems.

6. **CSpect-side instrumentation** (deferred). Would need lua hook /
   debugger logging on CSpect to trace the supervisor's full PC stream.
   Currently we only have point-sampling via DZRP BP. Consider only if
   single-point comparisons aren't decisive.

7. **Cleanup TEMP instrumentation** (`JNEXT_G46B_*` env-vars at
   `z80_cpu.cpp`) once welcome screen renders.

#### 15b — Build a minimal z88dk esxDOS NEX test program

Per Task 14 Q3: 40-60 LOC C, 5-6 esxDOS calls, builds via
`zcc +zxn -clib=new probe.c -o probe -subtype=nex -Cz"--clean" -create-app`.

Reference: `/home/jorgegv/src/spectrum/z88dk/libsrc/_DEVELOPMENT/EXAMPLES/zxn/esxdos/dir/dir.c`
(27 LOC working example). First test program asserts:

1. `esx_m_dosversion()` returns NextZXOS (not `$FFFF` or zero).
2. `esx_f_open("/NEXTZXOS/NEXTZXOS.MMC", ESX_MODE_R)` returns valid handle, errno=0.
3. `esx_f_read(handle, buf, 16)` returns 16 bytes, errno=0.
4. `esx_f_seek(handle, 256, ESX_SEEK_SET)` + read 16 more — bytes match expected.
5. `esx_f_close(handle)` then re-open immediately — handle reuse works.

The test program prints PASS/FAIL hex codes to screen so the regression
harness can MD5-compare the output to a reference image.

Add to `demo/` (where existing z88dk demos live; see CLAUDE.md building
section) with a `Makefile` integration, AND wire into the regression
suite as a new "esxdos-probe" case.

Effort: M.

#### 15c — Decide on asset-file strategy for blocking game NEX

`beanbros / celeste / celeste2 / trainyard-express` all fail at F_OPEN
of game asset files that aren't on our SD image. Two options:

- **Option α (provision):** add the needed asset files to the SD image
  alongside each NEX. Pros: tests the real esxDOS path end-to-end. Cons:
  bloats `roms/nextzxos-1gb-fat32fix.img`; per-game asset acquisition;
  legal/licensing review per game.
- **Option β (host-side esxDOS hosting shim):** intercept `RST $08;
  DB $9A` (and friends) at the emulator level and serve from host FS via
  a configurable mount-point flag (e.g. `--esxdos-host-fs <dir>`). Pros:
  zero-friction testing; no SD-image bloat; same flag works across all
  test programs. Cons: not VHDL-faithful (per `feedback_vhdl_faithful_only.md`)
  unless gated as an explicit test-only mode.

Recommendation: choose β with explicit `--esxdos-host-fs` flag, off by
default. Document as "test/dev mode only — NOT a production emulator
feature". Tests under the flag don't count toward regression baselines.
Decide before building 15b's z88dk probe so the probe can also use it.

Effort: M (β implementation) or S (α inventory + acquisition).

#### 15d — Document the three-layer test taxonomy

Per Task 14 strategic synthesis: jnext now has three complementary test
strategies, each probing different layers:

1. **Full-OS SD boot** — TBBlue.fw IPL + supervisor + every subsystem.
   Catches supervisor-level bugs. Currently blocked at G46(b).
2. **NEX autoload** (e.g. `celeste.nex`, `shift.nex`) — DivMMC + esxDOS +
   SD-SPI, bypassing supervisor. Catches runtime FS / driver bugs.
3. **z88dk minimal NEX** — same as (2) but with source control +
   assertion granularity. Best acceptance test, sub-2 s headless.

Add a short section to `doc/testing/REGRESSION-TEST-SUITE.md` or a new
`doc/testing/TEST-TAXONOMY.md` mapping each NEX/test in the regression
suite to its layer, so future investigations don't conflate them.

Effort: S.
