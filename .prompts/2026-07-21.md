## Task 1 — GH issue #46: macOS package fails to launch (v1.0)

Filed today from a **Kounch** report on the Telegram channel
(https://t.me/jnezt_rulez). `/Applications/jnext` aborts at launch:

```
dyld: Library not loaded: /opt/homebrew/opt/libpng/lib/libpng16.16.dylib
```

- Cause (to confirm): the `macos` job in `.github/workflows/release.yml` builds
  against Homebrew deps and packages with a bare `cpack -G DragNDrop`. Nothing
  copies the dylibs into the payload or rewrites install names, so the shipped
  binary keeps absolute `/opt/homebrew/opt/...` references. libpng is only the
  first failure; SDL2, Qt6, curl and openssl are almost certainly the same.
- The payload is a bare executable, not a `jnext.app` bundle, so there is no
  `@rpath` / `Contents/Frameworks` layout to fall back on.
- Fix direction: `MACOSX_BUNDLE` app bundle + `macdeployqt` and/or
  `fixup_bundle()`; assert with `otool -L` that no `/opt/homebrew` path remains.
- **Verification is the hard part.** No Mac on the dev host, the macOS release
  leg is `continue-on-error`, and it has only ever been verified as "builds and
  publishes a .dmg" (v0.98.34) — never as "runs on a machine that did not build
  it". Needs a `macos-build.yml` dispatch run asserting `otool -L`, or Kounch
  testing a rebuilt package. **A push will be needed to run CI — ask first.**
