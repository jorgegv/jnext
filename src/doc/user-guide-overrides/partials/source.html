{#- Override of Material's partials/source.html (GH #nit, 2026-07-23). Material's stock source block carries data-md-component="source", which its bundle.js reads to fetch api.github.com/.../releases/latest and show the latest release top-right. That value is cached in localStorage and went visibly stale. We drop that attribute so Material's cached fetch never runs, and show TWO facts instead: * "This version " — the jnext version THIS COPY of the guide was rendered from. Static, from config.extra.doc_release in mkdocs.yml, which packaging/sync-version.sh rewrites from version.yaml on every bump (re-rendering the guide in the same step). Baked at render time, so it is correct offline — the guide ships inside the packages. Deterministic: docs-check re-renders and byte-diffs, so nothing here may depend on wall-clock or network. * "Latest version " — version.yaml on GitHub main, fetched live. NOT the latest GitHub *release*: the point of the pair is "is the guide I am looking at current?", and a release tag would answer a different question (this guide is deployed from main, and main runs ahead of the last public release). Fails silently offline, leaving the em dash. The fetch must never serve a stale answer, so it defeats caching twice: cache: 'no-store' covers the browser, and a timestamp query parameter defeats the CDN in front of raw.githubusercontent.com, which 'no-store' cannot reach. Deliberately NO custom Cache-Control request header — that would make this a non-simple cross-origin request and force a preflight the raw host need not answer, trading a stale value for no value at all. The two stack one per line. Material lays its facts out as a flex ROW with an ellipsis, which put both on one line and truncated the first to "docs v0.99…" — unreadable, and the two were easy to mistake for one another.
